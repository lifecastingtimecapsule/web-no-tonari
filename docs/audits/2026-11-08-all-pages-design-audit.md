# 全8ページの横断デザイン監査

変更履歴: 2026-11-08 ページ遷移時に雰囲気が変わるという指摘を受け、公開画面・ソース・操作を横断して監査した初版。監査結果の記録のみで、サイト実装の修正・コミット・再公開はしていない。

## 結論

**サイト全体のデザイン統一性は不合格。最優先の原因は共通の外枠が存在しないこと。**

トップはロゴマーク付きの固定カプセル型ヘッダーと黒いフッター。下層7ページではマークが消え、通常フローの文字ヘッダーと白い簡易フッターに変わる。ページの役割が変わることとは別に、ブランドと回遊の目印が変わっている。

4つのサービス詳細同士は統一されている。会社概要・理念の読み物を静かにすること、問い合わせを白地・静止にすることはユーザーの希望に合っており、維持対象。サンプル内の花屋の緑・商品の砂色も、別事業の体験と明示されているため、サイト本体の不統一に含めない。

既存のAUDIT.mdにある個別ページの動作確認・detector合格は、この横断的一貫性の合格を意味しない。前回までの確認では、共通外枠がページをまたいで維持されるかの確認が不足していた。

## 優先所見

重複を統合して11件。P0: 0件、P1: 3件、P2: 6件、P3: 2件。P1の意匠所見は本サイトの「ページ間の一貫性」という目的に対する重大度であり、WCAG違反という意味ではない。

### P1-01 ロゴとヘッダーの外枠が遷移時に切り替わる

- 場所: `src/pages/index.astro:75`、`src/pages/services/[slug].astro:16`、`src/pages/seo-check.astro:9`、`src/pages/company.astro:28`、`src/pages/philosophy.astro:33`。外観は `global.css:180` と `services.css:3`。
- 影響: 同じサイトにいることを示す目印が消え、利用者が移動先を別サービスと認識しやすい。
- 修正: ブランドマーク込みの共通SiteHeaderにし、位置・高さ・ナビの基本構成を全ページで維持する。ページ固有のサービス切り替えは別の副ナビにする。
- 対応観点: `$impeccable layout`。

### P1-02 フッターと会社・理念への回遊が下層で失われる

- 場所: `src/pages/index.astro:291`、`src/pages/services/[slug].astro:22`、`src/pages/seo-check.astro:15`、`src/pages/company.astro:44`、`src/pages/philosophy.astro:52`。
- 影響: トップでは見つかる運営者・会社・理念が下層では見つからず、信頼情報を探し直すことになる。黒から白への全面切替も別サイト感を強める。
- 修正: 共通SiteFooterを作り、ブランド・運営者・会社概要・企業理念・問い合わせへのリンクを維持する。
- 対応観点: `$impeccable layout`。

### P1-03 入力境界とURL placeholderのコントラスト不足

- 場所: `src/styles/global.css:1135`、`src/pages/seo-check.astro:22`、`src/styles/services.css:45`、`src/components/OpeningHero.astro:63`。
- 事実: 問い合わせの白背景に対する枠 `#aab9c6` は2.01:1。SEO等の枠 `#b6b6bd` は白に2.02:1。URL placeholder `#777780` は白に4.44:1。
- 影響: 入力面の境界が分かりにくい。枠が操作領域の識別を担う箇所でWCAG 1.4.11の3:1、小さいplaceholderで1.4.3の4.5:1を下回る。
- 修正: 入力の境界・placeholder・focusを共通トークンにし、対比を十分に確保する。赤い背景へ戻す必要はない。
- 対応観点: `$impeccable harden`。

### P2-01 同じ相談先のラベルと視覚的な優先度が違う

- 場所: `src/pages/index.astro:94`、サービス `:16`、会社 `:28`、理念 `:36`、SEO `:9`。
- 事実: 「相談する」「相談内容をまとめる」「お問い合わせ」が別の見た目で同じ場所へ進む。SEO上部にはその入口がない。
- 修正: ヘッダー内の共通名・位置・形を統一。フォーム内の「相談内容をコピーする」は行為が違うため、現在の落ち着いた黒い操作として区別する。
- 対応観点: `$impeccable clarify`。

### P2-02 スマホの導入と画像クリック後の連続性が弱い

- 場所: `src/pages/index.astro:164`、`src/pages/services/[slug].astro:16`〜`:19`、`src/styles/services.css:69`。
- 事実: サービス詳細は文字ヘッダーと副ナビで上部が複数段になり、主見出しが約300px付近から始まる。体験画像を押しても、まず長い説明に着地する。
- 修正: 共通ヘッダーの下に副ナビだけを置く。画像からのリンクは該当ページの`#sample`へ、タイトル・詳細説明のリンクはページ冒頭へ、という分け方も有効。
- 対応観点: `$impeccable adapt` / `$impeccable layout`。

### P2-03 書体名は同じだがweightの読み込み規則が違う

- 場所: `src/pages/index.astro:69` と下層各ページのGoogle Fonts指定、`src/styles/global.css:164`。
- 事実: トップはZen Kaku Gothic Newの600を要求するが、下層は500/700/900のみ。共通h2とブランドのCSSには600がある。
- 修正: 同じheadで必要な書体・weightを読み込み、見出しを「販促」「詳細」「読み物」の用途別トークンで定義する。読み物の見出しをヒーローの大きさにする必要はない。
- 対応観点: `$impeccable typeset`。

### P2-04 現行デザイン規則に撤回済みの説明が残る

- 場所: `DESIGN.md:34` と `:36`。前者は白い問い合わせと文字帯撤去、後者は赤い文字帯から相談面へつなぐ説明。
- 影響: 後からページを追加する際、どれを現行とすべきか判別しにくい。以前の指示を復活させる原因になる。
- 修正: 現行規則と履歴を分け、共通レイアウトの境界を明示する。今回の監査では元の設計ファイルを修正していない。
- 対応観点: `$impeccable document`。

### P2-05 縮小モーション設定の動的変更への対応が分裂

- 場所: `src/scripts/site.ts:86`、`:126`、`:388`。
- 事実: 既存の切り替えとScrollTriggerは初回設定のみ。追加したヒーローだけはmatchMediaで閲覧中の設定変更へ対応する。
- 修正: 同じ条件管理にまとめ、条件が変わったらトリガーを解除して静止状態に戻す。会社・理念・問い合わせに演出を足す対応ではない。
- 対応観点: `$impeccable animate`。

### P2-06 空白だけの相談文を成功扱いする

- 場所: `src/scripts/site.ts:229`、`:271`、`:276`、`src/pages/index.astro:269`。
- 再現: 公開版でスペース3個を入力すると、requiredを通過し、trim後の空本文が「相談したいこと\n」としてコピー処理へ渡される。成功案内も出る。テストではコピー先を差し替えた。
- 修正: trim済み本文が空なら近接エラーを表示し、必須入力であることもラベルで示す。
- 対応観点: `$impeccable harden`。

### P3-01 ブラウザタブのブランドと共通headが不統一

- 場所: `src/pages/index.astro:66`、下層各head。
- 事実: トップのfaviconは青い旧配色で、下層7ページにはicon指定がない。トップにcanonical・OGがなく、一部下層にはある。theme-color指定もトップだけ。
- 修正: 共通headにロゴ・基本metaを集約し、title、description、canonical、index可否はページごとに指定する。SEOページのnoindexは意図的設定なので不具合に含めない。
- 対応観点: `$impeccable document`。

### P3-02 旧ヒーローCSSが現行スタイルと混在

- 場所: `src/styles/global.css:259`以降、旧`.hero`・`.cinema`系。
- 事実: 現在の入口は`.opening`。旧ヒーロー規則を含むglobal CSSを下層も読み込む。スタイルの見通しを悪くするが、重大な速度障害とは判定しない。
- 修正: 保管用の旧ソースと現行配信CSSを分ける。Three.jsは現行入口でimportされておらず、そのままブラウザへ配信されているとは判断しない。
- 対応観点: `$impeccable optimize`。

## 技術面の参考スコア

独立した技術担当Bの評価。**14/20という数値はページ間の意匠統一の合格を意味しない。意匠の統一は不合格。**

| 次元 | 点数 | 主な根拠 |
|---|---:|---|
| Accessibility | 3/4 | skip link、ラベル、focus、状態表示あり。入力境界に不足 |
| Performance | 3/4 | 静的配信、画像寸法・lazyあり。不要CSSが残る |
| Theming | 3/4 | 色・書体トークンあり。headとweight・一部状態に漂流 |
| Responsive | 3/4 | 全16ビューで文書横はみ出しなし。実機・拡大・タッチ未網羅 |
| Implementation Integrity | 2/4 | 4詳細は共通化、サイトの外枠は分裂 |
| 合計 | 14/20 | 部分実装の土台はあるが、共通部品の修正が必要 |

## 実際に確認できた動作と良い点

- 全8ページ×2幅で文書の横はみ出しなし。各ページのmain内h1は1つ。
- メニューの開閉とEscape、問い合わせ空入力とSEO空入力のエラー・フォーカス移動。
- 花屋の理由表示、ECのサンプルカート合計、AIの整理例、メール確認数の更新。
- 全8生成HTMLの内部リンクとフラグメントは技術担当が照合し、欠落0。
- 共通書体・白黒赤・ネイティブ操作・サンプル表記・未送信の明示は維持する。
- `outline:0`のURL欄はfocus-withinの代替表示があるため、フォーカス完全欠落とは判定しない。
- detectorは `impeccable detect src/pages src/components --json` を1回実行し、exit 0・出力`[]`。これはソースの機械検査であり、全ページの描画・遷移を保証する検査ではない。

## 修正の順序

1. 共通のLayout / SiteHeader / SiteFooter / Brand / headを作り、全8ページへ適用する。
2. ナビ名・相談の入口・現在地表示・標準ボタン・フォント読み込みをそろえる。
3. 会社・理念の読み幅、サンプル固有の配色、白い静止問い合わせは保ち、ページ固有の本文を載せる。
4. 入力コントラスト、空白チェック、動きの条件を修正する。
5. 撤回済みの設計記述と旧CSSを整理する。
6. `$impeccable polish` と全8ページ×PC/スマホの遷移監査を最後に行う。個別画面だけで合格にしない。

この順序は次の実装案であり、今回の依頼では実装・公開していない。
