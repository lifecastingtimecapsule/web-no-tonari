## 検証

- frontend-designの既存世界観を保つ方針、Impeccable audit / craft-floor、最新版Web Interface Guidelinesを適用。
- Chromium 1440×900 / 375×900の8ページ×2幅。全16ビューで文書の横はみ出しなし、h1は各1つ。各ページの上部・全体の32枚を確認。モバイルのメニュー開閉・Escapeも全8ページで確認。
- 全体画像の一部には未スクロールのlazy画像が含まれる。追加でトップのサービスへ実際にスクロールし、4画像ともnaturalWidth=952の読込成功を確認。これを表示不具合と誤判定しない。
- サービス横送り: 1440pxで1〜3→2〜4、768pxで1〜2→2〜3、375pxで1→2。
- 架空サンプル: 花屋の理由表示、EC赤土2点＋送料の合計5,400円、AIのEC問い合わせ整理、メール3/3か所の確認を実操作。
- 問い合わせ: 空白入力の拒否、正常文のコピー内容、閉じたメニューにEscapeしても本文入力のフォーカス維持を確認。クリップボードはテスト用受け口に差し替え、利用者の実際のクリップボードは変更していない。
- SEO: 429のテスト応答で取得不能文と目的別の一般ガイドを表示し、数値を創作しないことを確認。商品の購入という目的・対象URLがトップの相談文と任意URL欄へ引き継がれることを確認。ライブAPI成功を意味しない。
- Astro check: エラー・警告・ヒント0。8ページの静的ビルド成功。ブラウザのpageerror 0。
- Impeccable detectorを修正UIに1回実行: exit 0 / `[]`。機械判定のみで合格とはせず、画面と操作を併せて判定。
- 独立した見た目・技術レビューで共通外枠の解消を確認。追加指摘の現在タブと横向きメニューも修正・実測。
- 生成8HTMLの内部リンク・フラグメント欠落0、git diff --check正常。

画像は`work/design-fix/`に保存し、Gitの公開対象には含めない。

## 残る条件

- 受付用メールはユーザーが新設予定。実メール送信は未接続で、現在のフォームは入力内容のコピーのみ。この制約は画面上にも明記。
- SEOの安定した実測取得は専用API利用設定が必要。既知のキーなし429条件を今回のデザイン変更で解消したとは扱わない。
