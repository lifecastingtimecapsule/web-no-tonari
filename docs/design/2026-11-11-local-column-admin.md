# コラムとローカル専用管理画面

変更履歴: 2026-11-11 コラム追加と非公開管理の依頼に対応。ユーザーがローカル専用を選択。

## 目的と決定
小規模企業の経営者・個人事業主が、ハッキングへの備えと業務システムを平易に理解できるコラムを公開する。管理画面・下書き・認証情報はインターネットへ配信しない。

## 方法の比較
- 採用: このMacの127.0.0.1だけで動く管理画面。新しい外部サービスやアカウント不要。外出先からは使用不可。
- 不採用: 外部CMSや公開ログイン画面。リモート利用には便利だが、公開する認証基盤・費用・管理対象が増える。
- GPTの画面自体を認証基盤にはしない。今後このチャットから記事を編集する場合も、ローカル下書きと公開データを区別する。

## 機能
- 一覧、記事本文、共通ナビ・フッター、サイトマップ。
- 管理画面: 初回パスワード設定、ログイン、記事作成・編集、下書き保存、プレビュー、公開用反映、公開用から取り下げ、ログアウト。
- 公開用反映は公開データへ確定する操作。実サイトへの配信は既存GitHub Actionsで行う。画面に未配信の違いと公開手順を明記。管理サーバー自身はGit・クラウド認証情報を使用しない。
- 自由HTML・ファイルアップロード・外部画像・任意スクリプト・外部取得・外部AI接続は付けない。文章、見出し、箇条書きとHTTPS出典リンクのみ。
- 自分の下書き上書き事故を避けるためリビジョン一致を確認し、未保存変更の警告を付ける。

## 非公開と安全性
- .local/column-adminをGitとAstro公開から除外。公開対象は明示したsrc/data/columns.jsonのみ。
- 127.0.0.1固定、Host完全一致とOrigin検査、CSRFトークン、JSON限定。CORSを許可しない。
- 初回設定には起動時発行の一時コードが必要。パスワードは本人がブラウザへ入力し、scryptハッシュのみローカル保存。既定パスワードなし。
- HttpOnly・SameSite=StrictのセッションCookie、有効期限、ログアウト無効化、ログイン試行制限、リクエスト長制限、CSP・キャッシュ禁止。
- 公開側は管理APIを持たず、本文を文字列としてエスケープ。管理UIもtextContentで表示。
- このMacに侵入された場合や、同じOSアカウントでファイルを直接読む攻撃は防げない。バックアップの管理は別途必要。

## 実装計画
1. 本文検証・公開用射影、認証・保存処理とそれぞれの境界テスト。
2. ローカルHTTP管理API・管理UI。架空記事でログイン、CSRF、権限、サイズ、競合、公開分離を検証。
3. 公開コラム一覧・記事ページ、ナビ・サイトマップ。既存の白地・書体を継承し、スマホを確認。
4. ソースレビューと安全なローカル検査、ビルド、公開ファイルに下書き・認証情報がないことの検査。
5. 公開用ページだけ既存フローで配信。運用手順と検査結果を記録する。
