# コラム管理の使い方

変更履歴: 2026-11-11 非公開のコラム管理を導入。公開・非公開の境界と配信手順を記録。

## 起動・初回設定
1. SITEVEILのプロジェクトで `npm run columns:admin`。
2. ターミナルに出る「初回設定」のURLを、このMacで開く。末尾の一時コードは共有しない。初回設定前にサーバーを終了するとコードは無効になる。
3. 本人が10文字以上のパスワードを入力する。チャットへ送らない。設定後のログイン先は `http://127.0.0.1:8792/`。
4. ログインは30分で終了。2分前に保存を案内し、期限後は本文を画面から消す。未保存の記事は失われるため、こまめに下書きを保存する。
5. 終了はControl+C。サーバーを停止するとセッションも失効する。

管理画面はこのMacの127.0.0.1のみ。公開サイトの/adminや/api/articlesでは使えない。トンネル、ポート転送、共有サーバーへの移動を行わない。パスワード再設定・複数管理者・遠隔利用は今回の機能に含めていない。パスワードを忘れた場合は、自己判断で認証ファイルを消さず、ローカル設定の再作成を依頼する。

## 記事を書く
- 新しい記事を書く → タイトル、URL名、分類、短い説明、本文を入力。
- URL名は半角小文字・数字・ハイフン。保存後は固定。
- 本文は通常の文章。`## 見出し`、`- 箇条書き`、空行で段落。HTML・埋め込み・画像アップロードには対応しない。
- 「下書きを保存」はこのMacだけへの保存。まだ公開内容は変わらない。
- 「表示を確認」は保存・公開しないプレビュー。
- 他の画面で更新されていた場合は競合を通知。自動上書きしない。
- 確認用リンクは公式情報など内容を裏付ける資料。管理用に記録し、公開ページには資料欄を表示しない。

## 公開・更新
1. 下書きを保存し、内容を確認。
2. 「公開用に確定」を押す。`src/data/columns.json`に、選択した記事の公開項目だけを反映する。
3. このチャットへ「コラムを公開して」と依頼する。内容とビルドを確認し、既存のGitHub Actionsで配信する。手動の場合は同ファイルだけをコミットしてmainへpushし、配信完了を確認する。
4. 管理画面の「確定済み」はローカルの公開用データの状態で、インターネットでの配信完了を意味しない。
5. 「公開用から取り下げ」後も配信が必要。配信前は公開サイトに記事が残る。下書き自体は残す。

管理サーバーはGitやCloudflareの認証情報を使用しない。外部AIへの送信もしない。別の操作で公開JSONが変わった場合は上書きを止めるため、管理サーバーを再起動して差分を確認する。

## 保存場所
- 非公開: `.local/column-admin/auth.json`（scryptハッシュ）、`articles.json`（下書き）。Git対象外、Astroから読み込まない。
- 公開用: `src/data/columns.json`。明示して公開用に確定した記事のみ。現在は0件。
- 公開ページ: `/columns/` と `/columns/記事のURL名/`。
- コラムは一般向け公開コンテンツであり、顧客調査データの「発送後30日削除」とは別。顧客の情報・パスワード・調査原本を記事に記載しない。
- ローカル下書きは自動削除しない。バックアップが必要なら、公開用ファイルと分けて暗号化・アクセス制限する。同じMacの同じOSアカウントに侵入された場合の防御は、このログイン機能だけではできない。

## 検証コマンド
`npm test`、`npm run columns:test`、`SITE_URL=https://site-veil.com BASE_PATH=/ npm run build`。
`dist`には管理用ファイルや下書きを配置しない。ローカル管理には外部依存パッケージを追加せず、Node.js標準機能を使用。
