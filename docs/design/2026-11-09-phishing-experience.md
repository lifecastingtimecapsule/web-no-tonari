# 登録不要のフィッシング体験

## 確定した方向

ユーザーがGoogle / Jigsawのクイズ形式を選択し、名前・メール入力を省き、フィッシングの判定・怪しい箇所の指摘・危険なリンクを開いたときの演出を依頼した。前回の情報量過多を受け、SMS一通だけで完結させる。2026-11-09の参考候補一覧で保留した実装を、この選択に基づき再開。

## 体験

- 初期表示：iPhoneを参考にした受信SMSと、短い問い。フォームや開始前の登録はない。
- 怪しい箇所：番号・期限・URLの3箇所。押すと隣（スマホでは下）の同じ領域に短い説明。番号や期限だけでは詐欺と断定しない。
- 全体の判定：「フィッシングだと思う」で、この例の狙いと対策を表示。
- 疑似リンク：「リンクを開く（体験）」で赤い警告と一度だけ340msの表示演出。「情報を盗まれた」とは断言せず、偽の支払い画面への誘導を説明する。
- URL文字を押す操作は指摘、別ボタンは開く体験とラベルで区別。実際の外部遷移・入力欄・保存・送信・音・点滅はない。
- 結果後も他の箇所を調べられ、「もう一度見る」で初期化。
- 出典と困ったときの確認先は折り畳み。PHPは `/services/security/php/` の記事へ分離。

日本郵便の名称は説明対象として使い、公式教材・提携の表示はしない。番号は伏せ字、URLは予約ドメイン.test。番号を正規のSMS送信元として再現したという主張はしない。Googleの画像・文章・問題は転載しない。

## デザイン

frontend-design・Impeccableの指針を適用。白 #FFFFFF、本文 #151517（既存ink）、補助灰色、ブランド赤、受信吹き出し #E9E9EB、疑似警告 #FFF0F2。共通のZen Kaku Gothic / Noto Sans JPを維持し、端末内だけiPhoneに近いシステム書体。端末340px＋左揃えの判断欄、640px以下では縦積み。演出は疑似リンクの回答時のみ。

## 現行仕様：前後の接続と三問への拡張

2026-11-09の追加指示により、一問の仕様を次の三問へ拡張。見た目・箇所の指摘・判定・疑似リンクの演出は維持する。

1. 不在通知のSMS：急がせる期限、配送会社らしいURL、少額の手数料。
2. 請求書を装うPCメール：差出人名への信頼、メールのパスワードの要求、表示URLと行き先の違い。
3. アカウント停止を装うSMS：短い期限、oと0の一文字違い、認証コードの要求。

- 前後ボタンと「問題 n / 3」。初期HTMLでも一問だけ表示し、切替時は一問だけを残す。最終問の次は「最初の問題へ」。移動して戻った際の解説はその場で保持し、「もう一度見る」でその問をリセット。
- 3問はいずれもフィッシングを題材とした学習例。見分ける能力の診断や安全性の保証ではない。送信元・期限だけで必ず偽物と断定しない。
- 青葉商事・KURASHI・.test/.exampleは教材用。実在アカウント・外部への偽リンクは使用しない。
- 3問の結果IDを個別にし、問題切替は番号の通知と見出しフォーカスを更新。JavaScriptなしでは3問の解説を標準detailsで読める。
- サービス導入で「日々の更新」と「不審な連絡への備え」を示す。体験後はサイト側の管理状況確認へ戻る短い文章を置き、料金・相談につなぐ。PHP記事リンクも体験注記から相談欄へ移す。

## 現行仕様：解説から次問への導線

- 2026-11-09：ユーザーから次問ボタンが解説と離れているとの指摘。上部は「前の問題」と進捗だけにし、解説直下に「次の問題へ」（最終問は「最初の問題へ」）を配置。
- 箇所の指摘・全体の判定・疑似リンクのいずれでも解説と次問操作を表示。回答の2ボタンは隠し、「もう一度見る」で初期表示へ戻す。教材内の怪しい箇所は引き続き調べられる。
- 「リンクを開く（体験）」を「リンクを開く」へ短縮。外部遷移しない挙動と教材の注記は維持。
- 全解説に短い表示演出を適用し、縮小モーション時は省略。配色・書体・端末画面・設問は維持。
